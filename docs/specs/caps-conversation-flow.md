## Anatomy and accessibility

The root owns one native scrolling div with a focusable region role supplied by the public Brain viewport, one named log, Brain's post-render spacer, and a separate polite atomic status for completion announcements. Provider/viewport/content wrappers are not application responsibilities. Projected items stay direct children of the log; a custom row uses CapsMessageScrollerItemDirective as its host directive. Projected native jump buttons are selected outside the log. The root must receive a bounded height from its layout; contentClass controls padding/gap, not a second scrolling container.

aria-label, aria-labelledby, aria-describedby and tabindex target the owned viewport, not the generic root. Log label/labelledby follows the same accessible name. aria-relevant, aria-live and aria-busy target the log. `aria-live=off` and a separate `announcement` are Capsule accessibility adaptations, not Brain inputs or upstream defaults. Do not bind token text, history prepends or every status change to announcement. The application supplies one localized completion/new-message message and clears it when a new operation begins. Opting into log live announcements requires an application history policy.

Marker is neutral readable context with no implicit status, separator role, tabindex or interactive role. Current progress can explicitly use role=status; historical markers remain quiet. MarkerIcon is aria-hidden and preserves decorative CapsSpinner composition. Whole-surface links/buttons use the native directive and must not contain another interactive control. Structural MarkerContent can contain a separate native action.

## Reading history, first-encounter anchors and explicit navigation

The internal adapter subclasses the PUBLIC BrnMessageScroller service. It uses configure, set/clearContentElement, set/clearViewportElement, userScrollIntent, syncAfterScroll, handleContentChange, handleResize and the public commands/signals; SCROLL_POSITION_EPSILON and USER_SCROLL_KEYS are PUBLIC exports. It owns references to its own viewport/content DOM. It never reads/writes private service state or copies private geometry.

Brain examines newly encountered scrollAnchor rows before its free/follow branch. User-scroll intent alone therefore cannot protect history. Capsule records historical reading on a scoped wheel/touch/viewport scroll key, on an observed upward native scroll (including scrollbar dragging), and on an accepted explicit message/start command. Reaching the live edge or an explicit end command re-enables admission of subsequent new anchors. Nested viewport intent and descendant editor/control keys do not release an outer root's follow state.

For a direct row whose data-scroll-anchor is true when first encountered while historical reading is active, Capsule marks that row as suppressed for automatic anchor reconciliation. Only around the synchronous public super.handleContentChange call does it temporarily set the owned row's data-scroll-anchor=false; finally restores the true attribute. Visibility continues to see the semantic anchor. The row stays suppressed for later automatic reconciles even after jump-to-end, avoiding delayed replay of the old anchor. Future first-encounter anchors at the live edge are admitted normally. A false anchor state observed by reconciliation, followed by true, or a new row instance starts a new eligibility cycle. Attribute-only changes retain Brain's reconciliation timing; this adapter does not add an attribute observer. This policy never vetoes an explicit scrollToMessage request: callers can navigate directly to a suppressed row. Existing admitted anchors retain Brain's streaming anchor behavior until user intent releases it.

Brain continues to calculate prepend preservation, margins, spacer extent, alignment, resize and visibility. Browser contracts verify a stable visible row offset after prepend, no jump on an ordinary append/new anchor/progressive growth while history is being read, explicit navigation to a suppressed row, and follow restoration for a later new anchor.

## Keyboard, motion, identity and lifecycle

Native viewport scroll keys count as intent only when the viewport itself is the target. Wheel/touch intent belongs to the closest owned viewport. Native jump button honors disabled, inactive state and defaultPrevented, remains out of the tab sequence while inactive, and focuses the viewport after successful navigation. Smooth commands become auto when the viewport's actual owner window prefers reduced motion. The owned jump button also disables its inherited transition through scoped reduced-motion utility variants; this is not a global motion policy. No browser global is read during server rendering.

messageId is a local logical key, not an HTML id; two roots can use the same key. Application id/ARIA relationships remain stable and caller-owned. No random or static counter IDs are generated. Brain's spacer is created after rendering to preserve hydration. Each root owns its provider/controller, observer registration, teardown and focus target. observeVisibility is optional and must be paired with unobserveVisibility when the consumer stops observing.
