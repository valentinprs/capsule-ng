# Capsule loading — issue #44

## Anatomy and API realigned to Spartan (2026-10-07)

The current user instruction makes official Spartan documentation and the existing public Brain API the property reference. The earlier Carbon proposal is withdrawn.

- `<caps-spinner>` owns one decorative NgIcon. Its properties match Spartan Spinner: `icon` (default `lucideLoader2`) and `aria-label` (default `Loading`). Custom icons use the existing provideIcons mechanism. Native `aria-hidden` is a Capsule accessibility adaptation: a decorative spinner omits its status role/name when text or a parent status already describes loading. Dimensions/colors use `class`, as the official examples do. No size, isActive, overlay, title, events or focus behavior.
- `<caps-skeleton>` is an empty decorative placeholder with no properties. Shape/dimensions use `class`; its parent owns `aria-busy` and real replacement content. No variants, generated rows or random dimensions.
- `<caps-progress>` is itself the only progressbar through the public BrnProgress host directive. It owns its internal Brain indicator; consumers never compose an indicator. The three exposed inputs are exactly Spartan Progress: `value` (number/null/undefined, initially undefined), `max` (number, initially 100), and `getValueLabel` (BrnProgressLabelFn, default rounded percentage). Brain coercion, validation and loading/complete/indeterminate states remain unchanged. Native id/aria-label/aria-labelledby/aria-describedby target the semantic host directly, requiring no additional property aliases or generated IDs. Labels and helper content remain external, native and explicitly associated; they are not hidden inside a progressbar. No label, helperText, hideLabel, size, status, type or id input.

Progress fill uses value/max, with logical positioning in LTR/RTL. All animation/transitions stop with prefers-reduced-motion; an indeterminate bar stays visible. None of the three components creates a focus target or a value accessor; Skeleton/Progress create no live region. Loading buttons use native CapsButton. No input is retained merely because another library provides it.

Official sources checked 2026-10-07: [Spinner](https://www.spartan.ng/components/spinner), [Skeleton](https://www.spartan.ng/components/skeleton), [Progress](https://www.spartan.ng/components/progress). Repository source references: libs/helm/spinner/src/lib/hlm-spinner.ts, libs/helm/skeleton/src/lib/hlm-skeleton.ts, libs/helm/progress/src/lib/hlm-progress.ts, libs/brain/progress/src/index.ts and its public BrnProgress/BrnProgressIndicator declarations. Brain and Helm sources remain unchanged.
